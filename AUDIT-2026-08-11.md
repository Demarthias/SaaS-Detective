## 3. Marketing site — concrete defects

### 3a. The annual plan card contradicts itself (highest-value one-line fix)

`saas-detective.html`, Pro · Annual card:

- line 630 — headline price: **`$72`**
- line 632 — `$6.00/mo — commit for a full year` (correct math for $72)
- line 645 — button label: **`Get Pro — $90/yr`** ← stale

Site commit `8533e4b` updated the price and the per-month math but missed the
button. The card shows two different prices, and the contradiction sits on the
exact element the user clicks. Checkout itself charges the correct $72.

At $90/yr against $7.99/mo ($95.88/yr annualised) the annual plan reads as only
~6% off — an offer nobody takes. At $72 it is a real 25% discount. The stale
button is still advertising the bad version of the deal.

### 3b. The homepage has no install CTA

`index.html` is the most-trafficked page (123 visitors) and mentions SaaS
Detective 15 times, but contains **zero** `chromewebstore.google.com` links —
seven internal links to `/saas-detective` instead. Every visitor must make a
second hop before they can install, which is consistent with the unexplained
123 → 53 drop-off.

### 3c. Two dead paths that people actually followed

- `/pricing` — 4 views, 2 visitors. **No `pricing.html` or `pricing/` exists in
  the repo.** Internal links correctly use `/saas-detective#pricing`, so this is
  an external or historical link 404ing.
- `/blog/blog/saas-debt.html` — 3 views. **No `blog/blog/` directory exists.** A
  doubled path from a relative-link bug.

## 4. The funnel is unmeasurable as instrumented

Extension and website events share one namespace, producing impossible orderings:

| Event | Events | Unique users |
|---|---|---|
| `popup_opened` | 381 | 28 |
| `view_pricing` | 249 | **37** |
| `checkout_abandoned` | 63 | **52** |
| `checkout_page_viewed` | 1 | **1** |
| `clicked_payment_link` | 35 | 11 |
| `checkout_begin` | 31 | 10 |
| `license_activated` | 5 | 3 |

`view_pricing` (37 users) cannot exceed `popup_opened` (28) if both were
extension events — and they aren't. `view_pricing` fires from **both**
`popup.ts:156/603` **and** `saas-detective.html:948`. That is the actual defect:
three surfaces writing into one namespace with nothing to tell them apart.

Two things I initially got wrong here, corrected after checking the source:

- `checkout_abandoned` is **not** a stray unload handler. It is fired
  server-side by the worker (`src/index.js:293–320`) on Stripe's
  `checkout.session.expired` webhook, keyed on `client_reference_id`. It is
  legitimate — it just isn't an extension event, and the 52 users come from
  every expired session across the account's full history.
- The "null version" reading was **my own query artifact**. The extension stamps
  `extension_version`; I grouped by `version`, which only the website sets.
  Re-run against `extension_version`, extension events are versioned correctly.

`checkout_page_viewed` showing 1 user is not a bug either: it was only added to
`checkout.html` recently, and checkout gets almost no traffic.

**This is still a cause of not knowing why sales are zero** — you could not
separate extension from web from server events. Fixed in this pass (see below).

## 5. Verified healthy — ruled out

- **Pricing ladder across surfaces** — extension `STRIPE_PLANS` ($7.99/mo,
  $72/yr), site `checkout.html` `PLANS` (799/2000/4000/7200), and the worker's
  `CHECKOUT_PRICE_MAP` all agree. Extension and site repos are both pushed.
- **Worker checkout endpoint** — `/checkout/create-session` is POST-only (the
  404 on GET is a method artifact). Probe sessions created today priced all four
  terms correctly, including the new $72 annual.
- **The archived-price outage is already fixed** — worker commit `2a5a431`
  replaced `price_1TY31E…` ($90/yr), which had been archived in Stripe and was
  rejecting *every* annual subscription with `stripe_error`. Genuine
  revenue-blocking bug; resolved.
- **Live URLs** — `/saas-detective` (the extension's `TRIAL_URL`, no `.html`),
  `/saas-detective.html`, `/checkout.html?plan=12mo` all return 200.
- **Product claims accurate** — site says "800+ signatures" / "64 categories";
  actual is 802 across 64.
- **The `$99/yr` on line 529** is Wappalyzer's price in the competitor
  comparison table, not a SaaS Detective price. Not a bug.

## 6. Open risk — payment completion is unverified under current config

Worker commit `193533e` (2026-08-08) added `automatic_tax[enabled]=true`
alongside `billing_address_collection=auto`. Session *creation* is verified
across all four terms. But **payment completion is not**: the only two
successful charges in account history predate the tax change (timestamps
1779614825 and 1782340871, both before 2026-08-08). Nobody has ever completed a
payment through the current configuration. Stripe Tax on embedded checkout with
`auto` address collection is a known friction point — this is the one piece of
payment plumbing still worth an end-to-end test.
